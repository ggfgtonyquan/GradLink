# GradLink 低保真页面方案

日期：2026-06-22

## 页面设计原则

GradLink 第一版不是招聘官网，也不是工具后台。打开网站后，用户应该马上看到讨论内容，感觉这是一个“应届生正在交流求职信息”的社区。

设计原则：

- 移动端优先，手机访问体验优先于桌面大屏。
- 首页直接展示信息流，不做营销首屏。
- 页面密度适中，适合刷帖、快速判断帖子是否值得点开。
- 视觉保持干净、轻量、可信，不使用夸张渐变、大面积装饰图或广告式卡片。
- 交互路径短：看帖、发帖、评论、收藏都应该容易找到。
- 管理后台以效率为主，不追求复杂视觉。

## 移动端全局结构

手机端底部固定导航：

```text
首页      发帖      收藏      我的
```

导航说明：

- 首页：帖子信息流和筛选入口。
- 发帖：进入发布讨论页；如果资料未完善，先进入资料完善页。
- 收藏：查看收藏的帖子。
- 我的：资料、我的帖子、账号设置。

页面顶部保持轻量：

```text
GradLink            搜索图标 / 登录入口
```

登录后右上角可显示简单头像占位或省略，只要不抢占内容空间。

## 首页信息流

首页是最重要的页面，首屏应该直接出现真实帖子内容。

移动端结构：

```text
GradLink                         搜索

[最新] [热门] [面试经验] [Offer比较] [简历求助] ...

秋招面试被问到项目细节，怎么准备更稳？
最近投后端开发，感觉面试官一直追问项目里的并发和数据库...
#面试经验 #秋招进度
2026届硕士 · 计算机方向        评论 12   赞 38

两个 offer 怎么选：一线互联网测试开发 vs 银行科技岗
base 差距不大，一个强度高，一个稳定一些，想听听大家怎么看...
#Offer比较 #签约三方
2026届本科 · 软件工程          评论 26   赞 51
```

信息流帖子项包含：

- 标题，两行以内。
- 正文摘要，两到三行。
- 标签，最多展示 2 到 3 个。
- 作者半匿名信息。
- 评论数。
- 点赞数。
- 收藏状态可以用图标表达，不一定显示文字。

筛选区：

- 第一行固定放“最新”“热门”。
- 后面横向滚动展示标签。
- 标签选中后信息流刷新。

空状态：

```text
还没有相关讨论
换个标签看看，或者发布第一条讨论
```

加载状态：

- 使用简单骨架屏或轻量 loading。
- 不需要复杂动画。

## 搜索页

搜索可以从首页顶部进入。

结构：

```text
搜索讨论
[关键词输入框]

热门标签
[面试经验] [Offer比较] [简历求助] ...

搜索结果
帖子列表...
```

搜索范围：

- 标题。
- 正文。
- 标签筛选优先，关键词搜索作为补充。

第一版不做搜索联想和高级筛选。

## 帖子详情页

详情页重点是阅读和参与讨论。

结构：

```text
返回

秋招面试被问到项目细节，怎么准备更稳？
2026届硕士 · 计算机方向 · 2小时前
#面试经验 #秋招进度

正文内容正文内容正文内容...
正文内容正文内容正文内容...

[赞 38]   [收藏]   [举报]

评论 12

感觉你可以把项目拆成背景、难点、方案、结果四段准备...
2026届本科 · 软件工程 · 1小时前
[回复] [赞 6]

  回复：确实，我之前只背功能点，问到取舍就卡住了。

[写评论...]
```

评论规则：

- 支持一级评论。
- 支持一层回复。
- 不做无限嵌套。
- 评论输入框在移动端可以固定在底部，也可以放在评论区顶部。第一版建议放在底部，便于参与。

内容状态展示：

- 普通用户只看到已发布内容。
- 作者查看自己待审核内容时，显示“等待审核”提示。
- 管理员可以看到待审、隐藏、拒绝等状态。

## 发帖页

发帖页要尽量简单，不要像复杂编辑器。

结构：

```text
发布讨论

标题
[请输入想讨论的问题或经验标题]

正文
[详细描述你的背景、问题、经历或想法]

选择标签
[面试经验] [Offer比较] [简历求助] [秋招进度] ...

[发布]
```

交互规则：

- 标题必填。
- 正文必填。
- 至少选择 1 个标签。
- 最多选择 3 个标签。
- 提交时如果命中审核关键词，提示“内容已提交审核，通过后会展示”。
- 如果用户未完善资料，点击发布入口时跳转到资料完善页。

文案语气：

- 鼓励用户写清楚背景和问题。
- 不在页面上写大段使用说明。
- 表单占位文字要具体、简短。

## 资料完善页

资料完善页是发言前的门槛，但不能让用户觉得很重。

结构：

```text
完善应届生资料

昵称
[输入昵称]

学校
[输入学校]

学历
[本科 / 硕士 / 博士 / 专科]

专业或方向
[例如：计算机、金融、机械、产品运营]

毕业年份
[2026]

公开学校
[开关]

[保存并继续]
```

说明：

- 学校是否公开由用户自己控制。
- 即使学校不公开，也可以在后台保留资料用于社区可信度。
- 保存后回到用户原本想做的动作，比如继续发帖。

## 登录与注册页

第一版使用邮箱和密码。

注册结构：

```text
注册 GradLink

邮箱
密码
确认密码

[注册]
已有账号？登录
```

登录结构：

```text
登录 GradLink

邮箱
密码

[登录]
还没有账号？注册
```

说明：

- 不发送邮箱验证邮件。
- 不做找回密码。
- 注册后可以立即登录。
- 发言前仍需完善应届生资料。

## 收藏页

收藏页用于回看有价值的帖子。

结构：

```text
我的收藏

帖子列表...
```

空状态：

```text
还没有收藏
看到有用的讨论时，可以点收藏，之后在这里查看
```

## 我的页面

我的页面是个人中心，不做社交主页。

结构：

```text
昵称
2026届 · 计算机方向

我的帖子
我的收藏
编辑资料
账号设置
退出登录
```

未完善资料状态：

```text
完善资料后可以参与讨论
[去完善]
```

我的帖子里需要能看到：

- 已发布。
- 待审核。
- 被隐藏或拒绝。

## 管理后台

管理后台可以桌面优先，但手机上也要能基本使用。

后台导航：

```text
待审核     举报     用户     关键词
```

待审核列表：

```text
待审核内容

类型：帖子
命中关键词：培训、加微信
作者：用户昵称
内容摘要...

[通过] [拒绝] [隐藏用户]
```

举报列表：

```text
举报内容

目标：帖子 / 评论
原因：广告引流
举报次数：3
内容摘要...

[隐藏内容] [驳回举报] [封禁用户]
```

用户管理：

- 搜索用户。
- 查看用户状态。
- 封禁或解封。
- 查看基础资料。

关键词管理：

- 关键词。
- 风险等级。
- 处理动作。
- 是否启用。

后台视觉：

- 以表格、列表和操作按钮为主。
- 状态颜色清晰：待审核用橙色，隐藏/封禁用红色，已通过用绿色。
- 不做复杂图表。

## 桌面端适配

桌面端不需要完全不同的信息架构。

桌面布局建议：

```text
顶部导航：GradLink / 首页 / 发帖 / 收藏 / 我的

左侧或中间：帖子信息流
右侧：热门标签、发帖入口、社区提示
```

桌面端增强：

- 信息流更宽。
- 标签筛选更完整。
- 管理后台更适合表格操作。

桌面端不做：

- 大幅营销 Hero。
- 复杂门户首页。
- 多栏资讯站式布局。

## 视觉方向

关键词：

- 内容优先。
- 安静可信。
- 轻量清爽。
- 学生社区感。
- 不像招聘官网。

颜色建议：

- 背景：白色或极浅灰。
- 主文字：深灰。
- 次级文字：中灰。
- 主强调色：蓝绿色或清爽蓝色。
- 待审核：橙色。
- 警告和封禁：红色。
- 通过和成功：绿色。

组件风格：

- 卡片圆角控制在 8px 以内。
- 按钮和标签保持紧凑。
- 列表项分割清晰。
- 字号不要过大，避免社区页面像营销页。
- 图标用于搜索、收藏、点赞、返回、举报等常见动作。

必须实现：

- 首页信息流。
- 搜索页。
- 帖子详情页。
- 发帖页。
- 登录页。
- 注册页。
- 资料完善页。
- 收藏页。
- 我的页面。
- 管理后台：待审核。
- 管理后台：举报。
- 管理后台：用户。

可以后置：

- 通知页。
- 用户公开主页。

- 关注用户。
- 深色模式。
- PWA 安装提示。

## 前端验收标准

第一版页面可以按这些标准验收：

- 手机端打开首页时，首屏能直接看到帖子内容。
- 游客可以顺畅浏览帖子和评论。
- 未完善资料用户点击发帖时，会被引导到资料完善页。
- 发帖、评论、点赞、收藏、举报入口位置清晰。
- 帖子详情页阅读不拥挤，评论区容易参与。
- 管理后台能完成审核、举报、封禁和关键词维护。
- 桌面端不变形、不空旷，后台表格操作可用。
- 页面整体不像招聘门户或营销官网。
